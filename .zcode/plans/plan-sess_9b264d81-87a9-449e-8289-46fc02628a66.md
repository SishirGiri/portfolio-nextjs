## Convert 5 demos into portfolio routes + wire Live Demo buttons

**Goal:** Serve the 5 standalone HTML/CSS/JS demos as routes inside the existing Next.js portfolio (e.g. `/demos/chatbot`), then point each project's Live Demo button at its route. Single repo, single Vercel deploy — the demos go live wherever the portfolio goes live.

### Serving strategy — preserve demos untouched (no React rewrite)

The demos are vanilla JS that query the DOM at execution time, use bare relative paths (`style.css`, `script.js`), and one (digit-classifier) depends on a CDN `<script>` (TensorFlow.js) loaded before its own script. Rewriting all 5 into React components would be risky and pointless. Instead, **serve each demo's static files directly** and mount them in a Next.js page via sandboxed `<iframe>`.

For each demo route `/demos/<name>`:
- **Move** the demo's `index.html`, `style.css`, `script.js` from `demos/<name>/` into `public/demos/<name>/` so Next.js serves them as flat static files at `/demos/<name>/index.html` (and the bare relative paths resolve correctly).
- **Create `src/app/demos/<name>/page.tsx`** — a thin, full-viewport client page that renders a header-less, full-screen `<iframe src="/demos/<name>/index.html" title="...">` styled to fill the viewport. The iframe isolates each demo's CSS/JS/global vars (TensorFlow.js, etc.) from the portfolio and from each other — important because the demos set globals like `tf` and use `document` directly.
- This means **zero changes to any demo's HTML/CSS/JS** — they keep working exactly as built and verified.

The 5 routes:
- `/demos/chatbot` → `public/demos/chatbot/`
- `/demos/dashboard` → `public/demos/dashboard/`
- `/demos/rpg` → `public/demos/rpg/`
- `/demos/classifier` → `public/demos/classifier/`
- `/demos/tasks` → `public/demos/tasks/`

(Using short slugs for clean URLs; internally they map to the project slugs.)

### Iframe page template (`src/app/demos/[a per-route page].tsx`)

A small client component per route (~15 lines each):
```tsx
'use client';
const DEMO_DEMO_PAGE = ({ children }) => ( ... ) // not real code — illustrative
// Actually: a shared <DemoFrame src="/demos/chatbot/index.html" title="AI Chatbot"/> wrapper
```
A single reusable `DemoFrame` component (new, `src/components/DemoFrame.tsx`) renders the full-screen iframe + a "Back to portfolio" link + the page `<title>`. Each route file is a one-liner calling it. Keeps it DRY and the iframe `title` is set per-route for a11y.

`DemoFrame` also calls the existing `PageShell`? **No** — the demos are full-bleed apps, so the iframe fills the viewport edge-to-edge with no portfolio navbar. A small floating "← Back to portfolio" pill (top-left, above the iframe) provides navigation back. (Keeps the portfolio's visual language — dark glass pill, cyan accent — without constraining the demo layout.)
